## Definition

Switching loops occur when network switches are connected together in such a way that network traffic loops around infinitely instead of traversing the hops needed to travel from source to destination.[^1]

## Cause

It can happen when:

1. Physical cable connected to <u>2 ports of the same device</u>
2. <u>Two switches circularly</u> forwarding packet to each other on 2 (or more) ports. This one is harder to troubleshoot

## Example

Imagine two switches, **Switch A** and **Switch B**, connected by _two separate Ethernet cables_.

- A user (PC1) on Switch A sends a broadcast (e.g., "Who has IP 10.0.0.1?").
- Switch A sends the broadcast to Switch B over **both cables**.
- Switch B receives two copies. It forwards one copy to its local devices _and_ forwards both copies back to Switch A.
- Switch A receives four copies. It forwards them to its local devices and sends them back to Switch B.
- The number of frames doubles exponentially, creating a storm that renders the network unusable.

## Troubleshooting

From [^1]:

If you suspect a switching loop and part or all of the network is down, you should take the following steps to troubleshoot and trace the source:

1. <u>Rule out</u> other potential sources of an outage, like DNS issues, hardware failure, etc.

2. Note the <u>network topology</u>: single L2 switch, multiple L2 switches connected to a core switch, etc.

3. Start at the <u>top of the network switching hierarchy</u> where the loop is affecting network connectivity, for example, at the core switch in the diagram above. Then connect a laptop to the switch you determined to be the top of the hierarchy affected by the loop.

4. Start a continuous <u>ping</u> session to a device on your network with the command ping (IP Address) -t

   ![[assets/image-62.png]]

5. Pay attention to the <u>ping session time</u>: If a loop has happened, the ping time should <u>increase dramatically</u> as the broadcast storm overwhelms the network.

   ![[assets/image-63.png]]

6. While continuing the ping session, <u>unplug each uplinked switch</u> from the core, or each device from an access layer switch, if starting there.

7. <u>Monitor the ping</u> session after each uplink is disconnected for 30 seconds to see if the time decreases and normal network connectivity returns.

8. Once you see normal <u>network connectivity return</u>, you have narrowed down the source of the loop. In the case of Figure 2, after disconnecting the uplink to Switch C, the loop would go away and normal network connectivity would be restored.

9. Once you have found the source of the loop, disconnect it to remove the loop.

> [!tldr]
>
> 1. Rule out common causes
> 2. Monitor a device
> 3. Start unplugging switches
> 4. Continue until connectivity is restored
