## About

The main purpose of the **Builder pattern** is to provide an interface for create an object that requires complex configuration during instantiation.

For example, rather than passing 10 different arguments to a constructor (which may change), we can use builder pattern to pass only the arguments we need and leave the rest to its defaults.

According to the guide at https://refactoring.guru/design-patterns/builder , we create concrete builders that implements a `Builder` interface. But in most cases we usually skip the interface part and create a single builder instead.

The guide also introduces a `Director` class for providing a set of ready-made objects created using builder to use. This is useful when we are creating an API and want to provide some common defaults, such as providing ready-made themes in a widget library.
